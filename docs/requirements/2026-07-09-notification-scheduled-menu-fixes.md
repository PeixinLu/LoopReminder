# 通知、定点提醒与菜单栏列表优化方案

日期：2026-07-09

## 1. 需求理解

- 通知体周围存在不可见鼠标事件遮挡区，需要让透明区域透传鼠标事件，只保留可见通知卡片响应点击。
- 定点提醒的时间点不再支持启用/禁用，时间点默认全部有效；不想要某个时间点时直接删除。
- 定点提醒至少保留一个时间点，最后一个时间点不能删除。
- 时间编辑面板增加提示文案：`支持键盘输入，回车确定`。
- 菜单栏计时器列表需要限制最大高度，计时器过多时在列表区域内部滚动，避免菜单超出屏幕。

## 2. 非目标

- 不重做通知样式、动画、材质系统。
- 不改变定点提醒“每天固定时间触发”的产品语义。
- 不新增复杂校验弹窗。
- 不重构整个菜单栏菜单，只处理列表高度和滚动。
- 不改变现有时间选择器的输入能力，只补充提示文案。
- 不立即从数据模型中删除 `ScheduledTime.enabled` 字段，优先保留以兼容旧数据。

## 3. 用户路径

- 用户看到通知时，只有可见通知卡片本身响应点击；卡片外透明区域不再遮挡鼠标。
- 用户编辑定点提醒时：
  - 每个时间点默认参与提醒，不再显示开关。
  - 删除某个时间点后，该时间点不再提醒。
  - 只剩最后一个时间点时，删除入口不可用。
- 用户打开时间编辑面板时，能看到提示：`支持键盘输入，回车确定`。
- 用户菜单栏里有很多计时器时，菜单高度保持在合理范围，计时器区域内部滚动。

## 4. UI/交互规格

- 通知鼠标事件：
  - 可见通知卡片可点击，保持当前忽略/完成行为。
  - 卡片外透明区域不响应鼠标事件。
  - 启动提示无按钮时，点击卡片仍可关闭/忽略；卡片外不拦截。
- 定点时间点：
  - 移除时间点上的启用开关。
  - 新增时间点默认有效。
  - 只有一个时间点时，删除按钮禁用或隐藏；建议禁用并保留布局稳定性。
  - 添加时间点逻辑继续避免重复时间。
- 时间编辑面板：
  - 增加弱提示文案：`支持键盘输入，回车确定`。
  - 使用 caption/secondary 样式，不抢主操作。
- 菜单栏列表：
  - 计时器列表区域增加最大高度。
  - 超出高度后内部滚动。
  - 顶部“打开设置”、计时器标题/批量按钮、底部退出按钮保持固定可见。

## 5. 技术方案

- 通知遮挡：
  - 当前 overlay window/panel 的透明区域仍可能参与事件命中，不能只依赖 SwiftUI 视觉透明。
  - 优先在承载通知的 AppKit view/window 层处理 hit testing，让卡片外区域返回 `nil` 或透传事件。
  - 命中区域应基于 `overlayWidth`、`overlayHeight`、`position`、`padding` 计算，和视觉卡片位置保持一致。
- 定点时间点：
  - `ScheduledTime.enabled` 暂时保留用于 Codable 兼容，但业务逻辑不再依赖。
  - 新建、复制、保存、去重后的时间点统一视为有效。
  - `ScheduledTimesEditor` 中移除启用开关，删除动作增加 `times.count > 1` 保护。
  - 保存或切换到定点提醒时，如果 `scheduledTimes` 为空，自动补一个默认时间点。
- 定点调度：
  - `ReminderController` 调度定点提醒时不再过滤 `enabled`。
  - 定点提醒有效性从“至少一个 enabled 时间点”改为“至少一个时间点”。
  - 历史数据里的 disabled 时间点在新版中按普通时间点处理。
- 时间编辑提示：
  - 在 `TimeGridPicker` 或对应弹出编辑面板中增加说明文本。
- 菜单栏最大高度：
  - 将 `MenuBarView` 中计时器 `ForEach` 包入 `ScrollView`。
  - 给计时器列表区域设置可调最大高度，例如 `MenuBarPreviewTuning.timerListMaxHeight`。
  - 菜单栏 Preview 增加多计时器样例，便于调整高度和按钮观感。

## 6. 修改文件范围

- `LoopReminder/Views/OverlayNotificationView.swift`
  - 调整通知卡片透明区域命中行为，必要时新增辅助 view。
- `LoopReminder/Controllers/ReminderController.swift`
  - 若需要窗口层配合，调整 overlay panel/content view。
  - 定点调度不再过滤 `enabled`。
- `LoopReminder/Models/TimerItem.swift`
  - 保留 `ScheduledTime.enabled` 兼容旧数据，但默认和规范化逻辑按启用处理。
- `LoopReminder/Views/Settings/TimerManagementView.swift`
  - 移除时间点开关。
  - 限制最后一个时间点不可删除。
  - 增加时间编辑面板提示文案。
  - 保存/切换类型时补齐至少一个时间点。
- `LoopReminder/Views/MenuBarView.swift`
  - 菜单栏计时器列表增加 ScrollView 和最大高度参数。
  - 增加多计时器 Preview 场景。

## 7. 边界情况

- 历史数据里 `scheduledTimes = []`：打开编辑或保存时自动补一个默认时间点。
- 历史数据里 `enabled = false` 的时间点：新版按普通有效时间点处理，不再忽略。
- 用户快速连续删除：删除函数本身 guard，不能删到 0。
- 重复时间点：继续使用现有去重逻辑。
- 菜单栏计时器非常多：列表滚动，菜单顶部和底部操作仍可访问。
- 通知在不同位置显示：透明区域都应透传，只有实际卡片区域吃事件。
- 通知带操作按钮：按钮点击仍正常；卡片点击忽略仍正常。
- 启动提示无按钮：卡片点击仍可关闭，不影响启动提示 Preview。

## 8. 验收标准

- 通知卡片外透明区域不再遮挡鼠标点击或悬停。
- 通知卡片内部点击、忽略、完成按钮行为不回归。
- 定点提醒时间点不再显示启用开关。
- 新增时间点默认参与提醒。
- 删除时间点后，该时间点不再提醒。
- 最后一个时间点不能删除。
- 老数据里 disabled 的时间点进入新版后按普通时间点处理，不再被忽略。
- 时间编辑面板显示：`支持键盘输入，回车确定`。
- 菜单栏计时器很多时，菜单不会超出屏幕，计时器区域可滚动。
- 菜单栏顶部操作、批量开关、退出按钮仍可见可点。
- Debug build 通过。

## 9. 风险点

- 通知透明区域透传涉及 AppKit hit testing，若只在 SwiftUI `.allowsHitTesting(false)` 处理，可能无法解决 NSPanel 窗口级遮挡，需要窗口层配合。
- 通知卡片位置计算必须和 SwiftUI 布局一致，否则可能出现可见卡片边缘点不到或透明区仍挡鼠标。
- `ScheduledTime.enabled` 暂时保留但业务不使用，后续维护者可能误以为它仍有效，需要用注释或集中规范化降低误用概率。
- 菜单栏高度在不同屏幕尺寸、不同 macOS 菜单渲染下表现可能略有差异，固定最大高度需要后续视觉微调。
- 时间编辑提示位置如果放得太重，会让编辑面板显得拥挤，应使用弱说明样式。

# 唤醒后定点提醒恢复设计

## 目标

系统从锁屏或休眠恢复后，无条件扫描并恢复所有已开启的计时器；定点提醒按配置重新安排到下一个未来时间点，且不补发休眠期间错过的提醒。仅当用户开启“唤醒后重置”且休眠/锁屏达到 5 分钟时，循环提醒才从唤醒时刻重新倒计时。

## 范围

- 修改 `ReminderController` 的睡眠/唤醒、锁屏/解锁恢复路径与定点调度辅助逻辑。
- 不改变提醒编辑、持久化格式、通知样式或应用启动时的恢复行为。
- 不改用系统日历通知；提醒继续使用当前的应用内浮层机制。

## 行为

1. 控制器注册以下生命周期事件：
   - `NSWorkspace.shared.notificationCenter` 上的 `willSleepNotification` 和 `didWakeNotification`，作为系统睡眠与唤醒的正式恢复入口；
   - 保留 `DistributedNotificationCenter` 的锁屏与解锁事件，作为只锁屏、不进入系统睡眠的补充入口。
2. 进入睡眠或锁屏时记录开始时间；从睡眠唤醒或解锁时，无论选项是否开启，都扫描所有 `isRunning` 且内容有效的计时器，确保其运行时 `Timer` 已恢复。同一轮恢复只执行一次，避免唤醒后紧接着解锁导致重复编排。
3. 循环提醒的 P0 扫描：取消并重建所有运行时 `Timer`，按已记录的下次触发时刻恢复既有倒计时进度；若该时刻已在休眠期间经过，则安排为唤醒后立即触发一次，再继续原有间隔。不因扫描本身将倒计时从零开始。
4. 循环提醒的 P1 重置：仅当用户启用“唤醒后重置”、锁定/休眠时长达到现有的 5 分钟阈值时，取消循环提醒的旧任务，并从当前时刻开始新的完整间隔倒计时。
5. 定点提醒的 P0 扫描：取消其旧的一次性 `Timer`；每个配置时间点独立计算严格晚于当前时刻的下一次日期并重新安排。
6. 若系统实际进入睡眠，且配置时间点位于睡眠开始时间（含）到唤醒时间（不含）的区间内，视为已经错过：不展示、不播放、不写提醒事件，仅记录一条日志，例如：`定点提醒已错过（系统休眠）：喝水 - 09:30`。仅锁屏但未收到系统睡眠事件时不写该日志。
7. 唤醒后不存在未来重排失败的已开启定点任务；所有时间点均恢复为一个有效的一次性 `Timer`。

## 设计

- 将“计算下一次定点触发时间”抽成可注入 `now` 的纯计算函数，避免唤醒恢复过程对每个时间点读取不同的当前时间。
- 将“停止某一计时器的全部定点任务”抽成私有辅助方法，供手动停止和唤醒恢复共用，避免遗漏 `scheduledTimers` 与 `scheduledTimerOwners` 两份状态。
- 将当前 `handleUnlock()` 扩展为统一的恢复入口，并由 `didWakeNotification` 与解锁事件调用。恢复入口先执行不受选项控制的 P0 扫描：循环提醒全部重建并保留倒计时进度，定点提醒一律重排；再在选项开启且时长达到阈值时执行 P1 的循环倒计时重置。
- 睡眠/唤醒通知必须注册到 `NSWorkspace.shared.notificationCenter`；不将 `DistributedNotificationCenter` 的私有锁屏字符串作为系统唤醒的唯一信号。
- 错过判定使用 `Calendar` 按本地日期生成锁定日到唤醒日之间每个配置时间点的候选日期，覆盖跨日情形；仅用于日志，不影响下一次调度。

## 测试

- 纯时间计算：当前时间已越过 09:30 时，下次为次日 09:30；未越过时为当天 09:30。
- 错过检测：锁定于前一日、唤醒于次日时，识别跨日窗口内的多个定点；窗口外时间点不识别。
- 恢复编排：定点项目的每个时间点均得到一个未来触发时间，且不触发补发通知。
- 生命周期入口：系统唤醒与随后解锁只触发一次恢复；选项关闭或经过时长未达阈值时仍执行 P0 扫描；仅锁屏、不睡眠时也能触发恢复。
- 回归：循环提醒仅在选项开启且达到阈值时重置倒计时；其余情况下不改变倒计时进度。

## 取舍

该方案不能在应用完全退出或系统持续休眠期间主动送达提醒；它保证应用恢复运行后，定点任务不再停留在过期的内存定时器上。若未来需要在应用未运行时仍送达，应单独设计基于 `UNCalendarNotificationTrigger` 的系统通知方案。
